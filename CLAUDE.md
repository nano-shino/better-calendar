# Better Calendar

Google Calendar as a list of photo cards (Day / Week / Month). A static site
with no build step: plain ES modules that GitHub Pages serves from `main`, so
pushing to `main` deploys. Firebase Auth and Firestore hold settings; the
Calendar API is called from the browser.

Data flow and photos: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Workflow
and design rules: [CONTRIBUTING.md](CONTRIBUTING.md).

## Commands

```sh
npm run serve               # http://localhost:8000/?mock  (Node >= 22, nothing to install)
npm test                    # unit + headless Chrome (set CHROME_PATH if it isn't found)
npm run test:e2e -- panel   # only e2e files whose name contains "panel"
npm run screenshots         # PNGs at 3 sizes in tests/.artifacts/; REAL_IMAGES=1 loads real photos
```

Keep it dependency-free: no frameworks, bundlers or npm packages.

## Mock mode

`?mock` is a fake signed-in state with sample events and an in-memory store.
Every e2e test uses it. Sample events (`js/sample.js`) are relative to today,
and the tests freeze the clock at **Mon 2026-11-16 10:00, UTC, en-US**,
so changing the sample data means updating the e2e expectations.

## Where things are

- `js/main.js`: app state `S`, navigation, loading and caching, accounts, boot, `?mock` branches
- `js/views.js`: renders the list (DOM only, no fetching)
- `js/panel.js`: event panel, photo picker, flying-photo animation
- `js/photos.js`: which photo an event gets, picker search, uploads
- `js/curated.js`: generated by `tools/curate-photos/`; don't edit by hand
- `firestore.rules`: paste into the Firebase console when it changes; nothing here deploys it

## Rules learned the hard way

- **No View Transitions API.** While one runs, Chrome sends every pointer hit
  to the root, so clicks are lost. Animate with CSS classes and WAAPI instead.
- **`[hidden]` is `!important`**, because components set `display`. Toggle with `el.hidden`.
- **Prefix CSS classes with their component.** Generic names have collided before.
- **No guessed photos.** Automatic photos come only from the curated set, for
  titles matching `THEMES`. Never fill gaps with search results.
- **Firestore documents max out at 1 MiB**, so each upload is its own document,
  compressed below 750 KB.
- **Google tokens last about an hour** and there's no refresh token. They live
  in `localStorage` only, never in Firestore. Re-auth must start from a click,
  or the popup is blocked.
- **The scrim ignores clicks** within 350 ms of the panel opening, so a
  double-clicked card doesn't open and close at once.
- **Event links:** take `eid` from `htmlLink` with a regex; `URLSearchParams`
  turns `+` into a space.
- **Paths stay relative**, because the site is served from `/better-calendar/`.

## Tests

- E2E tests send real input over CDP. Don't swap in `element.click()`: overlay
  and hit-testing bugs must fail the tests.
- The network is stubbed: Openverse API calls return a fixture and remote images
  a tiny PNG. Curated thumbnails are also on `api.openverse.org`, so the stub
  matches images first.
- `signed-in.e2e.mjs` runs the real (non-`?mock`) boot against a fake Firebase,
  Google sign-in and Calendar API with realistic delays: use it for loading jank.
- `page.swipe()` holds still before lifting. A fling makes Chrome swallow the next tap.
- Fix a UI bug together with an e2e test. For visual changes, look at the
  screenshots at all three sizes.
